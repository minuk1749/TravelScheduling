같아 보이지만 합치지 않은 부분: 생성 입력·생활 설정·결과 제약은 서로 다른 DTO/오류 계약이다.
SQL의 레거시 시간/JSONB 정규화도 API 입력 검증과 목적이 다르다.
`settings/input.tripDates`는 1–31일 검사, `day-plan.tripDates`는 내부 날짜 열거이므로 그대로 둔다.
UI 상태/요청 처리의 유사한 모양만으로 새 공통 훅을 만들지 않았다.

## 성능 측정

재현: Node **24.22.3**, macOS arm64에서 `node --import tsx scripts/benchmark-itinerary.ts`.
동일 픽스처로 워밍업 3회 뒤 15회 측정한 중앙값. 변경 전 실행 후 동일 스크립트로 변경 후 실행했다.
Google/DB 지연은 포함하지 않는 **동선 계산 경로**의 측정이다. 실제 운영 응답시간 보장이 아니다.
매 계산마다 새 서비스/제공자를 사용하며 외부 응답 캐시 재사용에 따른 개선이 아니다.

| 시나리오 | 변경 전 중앙값 ms | 변경 후 중앙값 ms | 결과 |
|---|---:|---:|---|
| 도쿄 3일 정상 | 5.969 | 3.016 | 전체 결과와 제공자 호출 수 동일 |
| 도쿄 3일 초과 | 6.440 | 3.396 | 추천 조합·진단·효율 동일 |
| 도쿄 3일 고정 충돌 | 3.994 | 1.480 | 충돌/추천 없음 동일 |
| 20×20 요금 행렬 | 7.238 | 0.058 | 400칸 동일 |
| 100×100 요금 행렬 | 189.286 | 0.909 | 10,000칸 동일 |

스크립트는 전체 결과/호출 수(서비스) 또는 전체 변환 행렬의 SHA-256을 출력한다.
전후 동일 해시: 정상 `40e164f50010f068a302f03736dc2ea5b210ffbd674d33e4b3a92b11e8bddc76`,
초과 `7d852b4367f8e9fe9cb042fbc62182d7d6dc5152d41cc0de574e97c1cfecf79b`,
충돌 `942dd631387e98d6d800f297db3b0d9ae104010f0d630ec53d1d8c0c5a0456fe`,
20×20 `338ba8fb57008bfade090264336743d4cd1be0b0aa66ffe9227c683d3019bcc4`,
100×100 `c6ff8533c3b438ffc5d92276352dbdf934d880d039d2c2cae964e6cf67cf121b`.

자동 회귀는 시간 배율을 강제하지 않고 `fare-matrix.test.ts`에서 행렬별 포매터 생성 **1회**와
단일 구간 변환 동등성을 검사한다. 심야 경계·DST·프로필 없음·미상/무료/다른 통화·입력 불변성·오류 검증을 포함한다.
기존 3일/20방문 1초 제한 검사도 유지한다.

### 실행 결과

Node 24.22.3을 임시 디렉터리에 준비하고, 격리된 Docker PostgreSQL 16을
`DATABASE_URL`로 연결했다. 저장소 패키지/lockfile 변경 없이 실행했다.

- `npm run lint`: 통과.
- `npm run typecheck`: 통과(Next route 타입 생성 + strict tsc).
- `npm run build`: 통과(PWA 산출물 검사 포함).
- `npm test`: **144 통과, 0 실패, 0 skipped**. DB 연결·마이그레이션·입력/설정/제약/일정 저장 검사 포함.
  T13 인계에서 DB 미설정으로 실행하지 못했던 검사를 이번 환경에서 완료했다.
- `node --import tsx scripts/benchmark-itinerary.ts`: 변경 전/후 각 완료, 위 5개 결과 해시 일치.
- `git diff --check`: 통과. 보호 파일 diff 없음. 이동한 기존 테스트 30개의 이름/개수도 유지됨.
- 최종 검사에서 기존 실패/새 실패 없음. Playwright E2E와 실제 Google/OAuth/Maps는 이번 실행에 포함하지 않았다.

## 남은 문제

- `repositories/trip-inputs.ts`의 여행 최초 생성은 장소/항공/숙소/방문별 INSERT다.
  동선 생성의 반복 계산 경로는 아니므로 일괄 저장과 동시 생성 잠금 순서 검증은 별도 R 작업 후보로 남긴다.
- 서버 조립/인증 SQL의 프로세스별 풀과 팩터리 함수가 모듈별로 있다. 연결 수 관리 정책을 바꾸려면
  앱 수명/종료 정책과 함께 별도 검토한다. 이번에는 기능과 무관한 전체 컨테이너/DI 재작성은 하지 않는다.
- 보호 자동화 `local-runner.sh` 책임 분리와 작업표 담당 정합성은 러너 관리 작업에서 처리한다.
- T4D 실제 요금/환율, T14 공유, T15 전체 사용자 흐름 E2E와 실제 Google/OAuth/Maps 확인은 기존 후속 범위다.

결정·대안은 [T13A ADR](decisions/T13A-audit-and-fare-preparation.md)에 기록한다.
