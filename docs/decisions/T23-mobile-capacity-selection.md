# T23 모바일 필수 장소 선택과 재검증

## 결정

수용량 초과를 반환한 여행 생성·하루 생활 화면은 같은 모바일 필수 선택 화면으로 전환한다. 기존 제약 조회의 저장된 우선순위로 체크 상태를 초기화하고, 서버가 돌려준 추천 최대 개수와 초안의 현재 선택 개수를 함께 표시한다. 추천은 가능한 조합을 찾은 시점의 추정값이다. 사용자 조합의 수용 여부는 생성 API로 다시 평가한다.

필수 해제는 해당 장소를 희망으로 유지한다. 날짜·시각·순서가 고정된 장소는 해제할 조건을 모두 표시하고, 확인한 뒤에만 우선순위와 고정 제약을 함께 바꾼다. 기존 이동수단 고정과 다른 방문의 조건은 제약 요청에 보존한다.

초안이 바뀌면 기존 제약 PUT으로 저장한 뒤 생성 POST를 실행한다. PUT의 새 revision과 생성 결과의 inputHash를 비교한다. 저장 뒤 계산이 실패하면 새 revision과 저장된 선택을 유지해 POST만 재시도한다. 다른 편집과 충돌하면 현재 입력을 다시 읽을 수 있다. 실패한 검증에서 이름을 알 수 있는 문제 방문은 선택 목록 맨 위에 모으고, 공항·끼니 등 여행 조건의 문제는 날짜와 함께 표시한다.

## 이유

제약 저장과 계산은 별개 요청이므로 저장에 성공한 상태와 검증을 마친 상태를 구별한다. 입력 해시를 비교하면 다른 곳에서 바꾼 조건으로 계산한 결과가 현재 선택의 성공으로 표시되는 것을 막을 수 있다.

## 대안

- 추천 조합으로 초기 선택을 자동 변경하면 여행자의 저장된 우선순위와 달라진다. 현재 우선순위를 표시하고 직접 선택하게 했다.
- 재검증 요청마다 저장을 반복하면 실패 뒤 재시도 시 같은 변경을 되풀이한다. 성공한 PUT의 스냅샷을 재사용한다.
- 결과 라우트를 다시 열어 POST를 실행하면 검증 결과가 바뀔 수 있고 제공자 조회도 늘어난다. T22와 병행하는 동안 검증된 응답의 날짜별 일정을 앱 메모리에서 바로 표시한다.
