# T18 장소 추가 화면

## 결정

1. 여행 입력의 장소 단계는 `src/components/visit-entries.tsx`(`VisitEntries`)가 그린다. 방문 장소마다 줄 머리(유형 아이콘 + 장소 이름 + 필수/희망 표시 + 삭제), 장소 검색, 유형·체류시간·우선순위 값 줄을 둔다. 검증은 기존 `parseTripDraft` 그대로다.
2. 필수/희망은 아이콘과 글자로 함께 표시한다: `필수 · 일정에 배치`(체크), `희망 · 지도에만 표시`(별). 우선순위 선택지도 같은 문구를 쓴다. 희망 장소가 자동 배치된다고 오해할 표현을 쓰지 않는다.
3. 장소 검색(`PlacePicker`)은 아이콘이 있는 검색칸, 결과 줄, 선택한 장소 줄로 바꾼다. 같은 목록에서 이미 고른 장소는 결과에 `이미 추가함`을 표시하고, 다시 고르면 바로 아래에 경고한다. 선택 자체는 막지 않고 저장 시 기존 검증이 중복을 거부한다.
4. 캔버스의 '상단 검색 → 결과에서 추가' 흐름 대신 '장소 추가 → 그 줄에서 검색' 흐름을 유지한다.
5. 날짜·시각·순서 고정은 여행 만들기에 없다. 기존대로 결과 화면의 장소 편집에서 설정하며 그 화면은 T19·T20에서 바꾼다. 캔버스 2-6(장소 설정 시트의 고정 조건 오류)은 결과 화면의 장소 수정으로 옮겨 적용한다.
6. 상태: 추가한 장소 없음(빈 줄), 검색 중(버튼 `검색 중…` + 자리 표시 줄), 검색 결과 없음(상태 문구), 이미 추가한 장소(배지·경고), 입력 오류(항목 아래).

## 이유

- 검색 결과와 방문 줄을 분리하면 '어느 줄에 들어갈 장소인가'를 다시 정하는 단계가 생기고, 여행 생성 API·검증·테스트 계약(`방문 장소 N 검색`)이 바뀐다. 줄 안 검색은 같은 정보를 한 흐름으로 입력한다.
- 중복을 결과 단계에서 막으면 검색 결과가 사라지는 이유를 설명해야 한다. 표시와 경고로 알리고 최종 판정은 한 곳(`parseTripDraft`)에 둔다(같은 규칙 중복 방지).
- 고정 조건은 계산된 일정이 있어야 의미가 분명하다(어떤 날짜·순서인지). 여행 생성 데이터 형식을 바꾸지 않는다.

## 대안

- 상단 검색 + `추가` 버튼: 캔버스와 같지만 위 이유로 보류.
- 이미 추가한 장소를 결과에서 비활성화: 사용자가 다른 줄의 장소를 바꾸려는 경우를 막는다.
