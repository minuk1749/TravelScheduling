# T13 결과 화면과 입력 제약 영속화

## 결정

- `/trips/[id]/result`에서 날짜별 타임라인, 구간 대안, 전체 효율, 원래 요청의 실패와 추천 조합을 표시한다. `CONFLICT`와 미검증 결과에는 타임라인을 표시하지 않는다.
- `GET/PUT /api/trips/[id]/constraints`는 인증·소유권·동일 출처·입력을 확인한다. GET은 입력 스냅샷과 revision(동선 inputHash), 실시간 장소 표시 정보를 반환한다. PUT은 `{ revision, constraints: { visits, legModes } }`를 받고 새 입력/revision을 반환한다.
- 방문별 필수/희망, 날짜·현지 시각·0 기반 순서는 기존 `trip_places`에 저장한다. 이동수단은 `trips.leg_modes` JSONB에 날짜·출발 장소·도착 장소 쌍으로 저장한다(마이그레이션 006). 구간이 사라져도 제약은 남고 다시 생기면 적용된다. 개별 구간 자동 선택과 전체 해제를 제공한다.
- 저장은 여행 행 잠금 아래 소유권과 전체 입력 해시를 다시 검사한다. 모든 장소를 여행 소속 ID로 검증하고 한 트랜잭션으로 갱신한다. 생성 서비스는 일상 구간의 기존 짐 정보를 보존하며 수단 제약을 덧씌우고 공항 이동에도 수동 선택을 적용한다. T12B의 날짜별 짐 처리 함수는 수정하지 않는다.
- 저장 후 기존 POST 생성 API로 재검증한다. 생성 응답에 `inputHash`를 추가해 화면 입력과 다른 결과 표시를 막는다. 저장과 생성은 별개 요청이므로 외부 API 실패에도 저장한 제약은 유지되며 재시도할 수 있다. 실패한 저장은 초안을 보존한다.
- 결과 화면을 다시 열면 저장된 입력을 불러오고 명시적 버튼으로 새 동선을 생성한다. 과거 결과 자동 복원·자동 외부 API 호출은 제공하지 않는다.
- 생활 설정 저장 뒤에도 같은 생성 API를 호출한다. 입력 중 시간창 미리보기와 저장 후 전체 동선 검증을 구분한다.
- Google Maps JavaScript의 AdvancedMarkerElement를 사용한다. 배치는 ●, 희망은 ☆, 필수 미배치는 △로 색·모양·텍스트를 구분한다. 마커 클릭과 접근 가능한 목록 모두 동일한 날짜 편집기로 연결한다. 키/지도 ID가 없거나 로딩 실패 시 목록으로 편집할 수 있다.
- 이름·귀속 정보는 요청 때 조회해 화면 메모리에만 유지한다. 장소 ID/좌표 외 상세 정보를 DB에 저장하지 않는다. 브라우저 Maps 키는 서버 Places/Routes 키와 별도이며 HTTP referrer/API 제한을 적용한다.

## 이유

결과 행을 직접 고치면 다시 계산할 때 수정 사항이 사라진다. 입력에 제약을 저장하고 기존 순수 스케줄러로 다시 검증하면 고정 항목·영업시간·이동수단 규칙을 중복 구현하지 않는다. 입력 해시는 생활 설정 변경과 생성 중 변경까지 감지한다.

## 대안

- 생성된 stops/legs 직접 수정: 다음 생성에서 유실되므로 제외.
- 브라우저/localStorage에만 저장: 재접속과 다른 기기에서 복원할 수 없고 장소 상세 정보 보관 문제도 있으므로 제외.
- 외부 호출을 포함한 DB 트랜잭션: 잠금을 오래 점유하므로 저장과 재계산을 분리.
- 신규 지도 엔진/자체 배경지도: 기존 Google 장소 제공자와 연결되는 공식 지도 어댑터를 선택.

지도 공식 문서: [API 로딩](https://developers.google.com/maps/documentation/javascript/load-maps-js-api), [고급 마커](https://developers.google.com/maps/documentation/javascript/advanced-markers/add-marker).

Google 실제 지도/OAuth/요금 출처 검토는 별도 사람 확인이다.
