# T14 읽기 전용 공유 링크

## 결정

- 소유자가 결과 화면에서 POST `/api/trips/[id]/share`로 링크를 발급·재발급한다.
  매번 난수 32바이트(base64url 43자)를 생성하고 기존 `trips.share_token`에는 SHA-256
  해시만 저장한다. 기존 UNIQUE 인덱스를 사용하며 마이그레이션은 필요 없다.
  원문은 발급 응답의 상대 경로(`/share/{token}`)에만 포함한다. 다시 열면 재발급해야 한다.
- 세션·소유권·Origin을 검사하고 UPDATE의 WHERE에도 owner_id를 넣는다.
  원자적 UPDATE 한 번으로 교체하므로 동시 재발급에서도 마지막 링크 하나만 유효하다.
- GET `/api/share/[token]`만 비로그인 열람을 허용한다. 기존 수정 API는 공유 토큰을
  읽지 않고 세션·소유권을 계속 요구한다. 토큰을 소유자 권한으로 승격하지 않는다.
- 최신 저장 일정(`generation DESC`)을 T12 정규화 테이블에서 복원한다. 여행 입력과
  일정은 하나의 REPEATABLE READ, READ ONLY 트랜잭션으로 읽는다. 입력 해시가 다르거나
  일정이 없거나 T12 상세 필드가 없는 과거 결과는 409로 재생성을 안내한다.
  GET이 동선을 계산·저장하거나 Routes API를 호출하지 않는다.
- 공유 DTO에는 표시용 기간·IANA 시간대·방문 ID/장소/우선순위·계산 결과만 담는다.
  사용자 정보, 여행 ID, 입력 해시, 생활 설정, 원본 항공 입력, 토큰 해시는 반환하지 않는다.
  지도·타임라인·비교 컴포넌트는 표시 DTO를 공유하고 편집 콜백이 없으면 수정 UI를 만들지 않는다.
- 이름·좌표·귀속 정보는 기존 장소 포트에서 요청마다 조회하고 저장하지 않는다.
  결과 편집과 공유 조회가 같은 표시 정보 함수를 사용하고 Google 장소 ID별 중복 요청을 제거한다.
  제공자 조회 후 토큰 유효성을 다시 확인해 조회 중 재발급된 링크의 응답을 차단한다.
- API 응답은 `private, no-store`, `no-referrer`, `noindex, nofollow`이며 공유 페이지도
  동적 렌더링·검색 제외·referrer 금지를 설정한다. 브라우저 API 조회는 세션 쿠키 없이 수행한다.

## 이유

읽기 권한을 별도 경로에 한정하면 기존 편집 권한 계약을 유지할 수 있다. 해시 저장은 DB에서
공유 가능한 원문 링크를 노출하지 않는다. 저장 결과를 조회하므로 공유 방문이 재계산이나
입력 변경을 유발하지 않고, 수정 중인 입력과 과거 결과를 혼합하지 않는다.
일정·지도 표시 코드를 재사용하되 편집기와 공유 화면의 책임은 분리한다.

## 대안

- JWT 링크: 즉시 무효화를 위해 결국 서버 상태가 필요하므로 채택하지 않았다.
- 별도 공유 스냅샷 JSON 저장: 기존 결과와 중복되고 Google 상세 저장 정책을 복잡하게 하므로
  채택하지 않았다. 링크는 고정 스냅샷이 아니라 최신 저장 결과를 가리킨다.
- 공개 API에서 일정 재생성: 열람이 쓰기·Routes 호출을 유발하므로 채택하지 않았다.
- 공유 토큰으로 기존 API 권한 우회: 수정 권한에 전파될 위험이 있어 채택하지 않았다.

## 검증과 한계

- `tests/sharing-http.test.ts`: 비로그인 읽기, 수정 API의 401, 소유권/Origin,
  재발급과 느린 제공자 중 재발급, 토큰 형식/해시, 캐시·오류·DTO 범위를 검사한다.
- `tests/sharing-db.test.ts`: 실제 결과 복원, 정상/초과/충돌, 최신 결과·입력 변경 감지,
  원자적/동시 재발급, 타인 쓰기 거부, 삭제 후 무효화를 PostgreSQL 16에서 검사한다.
- `tests/sharing-ui.test.ts`, `tests/e2e/sharing.spec.ts`: 발급·복사·재발급 UI,
  편집 없는 지도·타임라인, 무효 링크, 재시도, 375px와 실제 라우트의 쓰기 405를 검사한다.
- 이미 전달된 화면·복사본까지 회수할 수는 없다. 재발급 이후 서버 조회를 거부한다.
  실제 Google Maps/Places 표시와 OAuth는 키 없이 목으로 검증하며 사람 확인이 필요하다.

## 이번 실행 결과

Node 24.22.3과 임시 Docker PostgreSQL 16에서 `npm run lint`, `npm run typecheck`,
`npm run build`, `npm test`가 통과했다(전체 150개, 실패/skip 0).
추가 `npm run test:e2e -- tests/e2e/sharing.spec.ts tests/e2e/result.spec.ts`는 Chromium을
설치한 뒤에도 Mac 샌드박스의 `bootstrap_check_in ... Permission denied (1100)`로
브라우저 시작 단계에서 차단되어 시나리오를 실행하지 못했다. 테스트를 생략 처리하거나
실행 정책을 우회하지 않았다. 브라우저 실행이 가능한 환경에서 재확인이 필요하다.
