# T16 디자인 시스템 기초

## 결정

1. 디자인 토큰을 `src/app/globals.css`의 `:root` CSS 변수로 둔다. 컴포넌트 CSS는 변수만 쓴다. 규칙 문서는 [docs/design.md](../design.md).
2. 글꼴은 `pretendard` 패키지(1.3.9, SIL OFL 1.1)를 의존성으로 추가해 자체 호스팅한다. `layout.tsx`에서 동적 서브셋 CSS를 불러와 필요한 글자 묶음만 받는다.
3. T16은 기존 클래스 이름과 마크업, 접근성 이름을 바꾸지 않고 시각 규칙만 바꾼다. 화면 구성 변경은 T17–T20에서 화면별로 한다.
4. 테마 색(`themeColor`, manifest `theme_color`·`background_color`)은 새 바탕색 `#F2F4F6`으로 맞춘다.
5. 앱의 입력 흐름(여행 → 항공 → 숙소 → 장소 단계 입력, 저장 후 생활 설정 페이지)은 유지한다. 캔버스의 '여행 만들기' 한 화면은 두 페이지에 나눠 적용한다.

## 이유

- 토큰을 한 곳에 두면 색 조합을 바꿀 때 컴포넌트를 함께 고치지 않아도 된다(같은 규칙의 중복 방지).
- 외부 글꼴 CDN은 개인정보·가용성 의존이 생기고 PWA 오프라인 정책(온라인 전용)과 무관하게 매 요청 외부 호출이 생긴다. 자체 호스팅은 빌드 산출물에 포함된다.
- 흐름을 바꾸면 여행 생성 API·생활 설정 상속 규칙(ADR 0006, 0007)과 E2E 흐름까지 바뀐다. 시각 개선과 흐름 변경을 분리한다.

## 대안

- CSS-in-JS·디자인 라이브러리 도입: 새 런타임 의존성과 서버 컴포넌트 제약이 생겨 채택하지 않음.
- `next/font/local`로 가변 글꼴 한 파일(약 2MB) 로드: 첫 화면 전송량이 커서 동적 서브셋 CSS를 택함.

## 남은 결정 (사람 확인)

- 도로를 따라 칠하는 경로 표현에는 구간별 경로 모양(polyline)이 필요하다. 현재 이동시간 제공자는 행렬(시간·요금)만 받는다. Routes `computeRoutes`의 `polyline` 필드를 받으면 호출·비용이 늘어난다. T19는 경로 모양이 없으면 두 지점을 잇는 선·곡선으로 그린다. 상세는 [질문 목록](../questions.md) T16 행.
