# T28 희망 장소 누락과 영업시간 미상 처리

## 결정
- `services/itinerary/places.ts`의 `resolvePlaces`는 상세 정보가 없는 장소가 **고정하지 않은 희망 장소(WISH, 날짜·순서 미고정)만** 쓰는 경우 오류로 만들지 않고 건너뛴다. `schedulerVisits`는 위치를 얻지 못한 방문을 스케줄러 입력에서 뺀다. 필수·고정 방문과 공항·숙소가 같은 장소를 쓰면 기존처럼 `ItineraryInputError`다. 제공자 장애는 전파한다.
- 영업시간은 세 상태를 구별한다: 정상(구간 있음, 검사), 휴업(`[]`, 배치 불가 → `TIME_WINDOW`), 미상(`undefined`, 검사 없이 배치). `ItineraryResult.openingHoursUnknown?: string[]`는 표시 중인 일정에 배치된 방문 중 미상인 방문 ID다. 선택 필드이므로 이전 응답·저장 행과 호환된다.
- 저장: `itineraries.details`에 선택 필드로 보관하고 공유 조회가 복원한다(마이그레이션 없음).
- 표시: 앱 `CardModel.hoursUnknown`이 카드와 전체 일정에 "영업시간 확인 못함" 줄을 보인다. 이동시간 검증 실패는 기존대로 충돌 원인 메시지이며 서로 섞이지 않는다. 웹 진단 목록에도 같은 안내를 둔다(T25까지).

## 이유
- 희망 장소는 자동 배치되지 않으므로 좌표 없이도 일정 계산 결과가 같다. 한 곳의 조회 실패로 전체 생성이 막히면 안 된다.
- 영업시간을 확인하지 못한 것과 이동시간을 확인하지 못한 것은 사용자가 취할 행동이 달라 같은 메시지로 합치지 않는다.

## 대안
- 누락된 희망 장소를 `unplaced`에 별도 사유로 추가: 스케줄러 계약 변경이 필요하고 현재 화면이 이미 희망 장소를 미배치로 다루므로 채택하지 않았다.
- 미상을 `verification`에 포함: 서로 다른 의미가 섞여 채택하지 않았다.
