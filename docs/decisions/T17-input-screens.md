# T17 여행 만들기·생활 설정 화면

## 결정

1. 입력 화면은 구역 카드(`FormCard`) 안에 값 줄(`FieldRow`: 아이콘 타일 + 값 + 항목 이름 + 오른쪽 보조 값)을 쌓는다. 공용 표시 요소는 `src/components/form-rows.tsx`에 둔다(상태·입출력 없음).
2. 캔버스의 '값 줄 + `변경` 버튼 → 시트' 대신 브라우저 기본 입력칸(date·time·select)을 줄 안에 그대로 둔다. 줄의 큰 글자가 입력칸이고, 항목 이름이 그 접근성 이름이다.
3. 오류는 해당 항목 바로 아래(`FieldError`)에 보이고 입력칸에 `aria-invalid`·`aria-describedby`를 단다. 화면 낭독기용 요약 알림(`role="alert"`)은 하나만 두고 시각적으로 숨긴다. 제출 실패 시 첫 오류 입력칸으로 초점을 옮긴다. 특정 항목에 붙지 않는 오류(저장 요청 실패, 장소 단계 오류)는 버튼 위 목록에 보인다.
4. 값을 고치면 그 항목의 오류 표시를 지우고, 다음 제출에서 다시 검증한다.
5. 상시 안내 문장(현지 시각 안내, 숙소·짐 설명, 프로필 정책 설명, 시간창 미리보기 설명)을 뺀다. 시간대는 도시·항공 시각 줄의 보조 값으로 보인다.
6. 입력 흐름(단계형 여행 입력 → 생활 설정 페이지)과 검증 규칙·API는 바꾸지 않는다. 장소 단계는 T18에서 바꾼다.

## 이유

- 기본 입력칸은 날짜·시각 선택기, 키보드, 화면 낭독기 지원을 그대로 쓴다. 시트를 새로 만들면 모든 날짜·시각 입력의 접근성과 테스트를 다시 만들어야 하는데, 얻는 것은 시각 차이뿐이다.
- 접근성 이름을 유지해 기존 단위·E2E 테스트(`getByLabel`)가 화면 구조 변경 뒤에도 같은 계약을 검증한다.
- 요약 알림을 하나로 유지하면 오류가 바뀔 때 한 번만 읽히고, 보이는 문구는 항목 옆에 있어 어디를 고칠지 바로 보인다.

## 대안

- 줄을 누르면 시트에서 값을 고르는 방식: 캔버스와 가장 가깝지만 위 이유로 보류. 사용자 조사에서 필요하면 별도 작업으로 한다.
- 오류 요약을 보이게 유지: 항목 옆 문구와 같은 내용이 두 번 보여 화면이 길어진다.
