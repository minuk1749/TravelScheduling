# ADR 0003: 장소 프록시와 허용 필드 캐시

날짜: 2026-11-18 · 작업: T8

## 결정

- `PlaceProvider`의 한국어 검색/상세 포트를 구현하고 `location(googlePlaceId)` 포트를 추가한다.
  인증한 사용자만 서버의 Google Places API (New) 어댑터를 호출한다. 키는 서버 환경 변수로 받는다.
- 좌표만 프로세스 메모리에 기본 24시간, 최대 1,000개 보관한다. 만료 타이머가 미조회 항목도 삭제하며,
  조회 시에도 만료를 검증한다. 테스트/다른 서버 설정의 TTL도 7일을 초과할 수 없다.
  재시작·다른 프로세스·용량 초과 퇴출 뒤에는 다시 조회한다.
- 이름·유형·영업시간·검색 결과·attribution은 저장하지 않는다. 상세 응답의 `cacheExpiresAt`은
  조회 완료 시각으로 즉시 만료하며, 좌표만 추출하여 별도 캐시에 넣는다. `location` 응답의
  `cacheExpiresAt`은 좌표 캐시 만료 시각이다. 실패/404는 캐시하지 않는다.
- 기존 `places` 테이블은 변경하지 않는다. T7A의 미래 `PlaceRepository.findDetails/saveDetails`
  계약은 Google 전체 상세 보관을 전제하므로 도입하지 않는다. T10에서 장소 연결을 저장할 때는
  내부 UUID와 Google place ID만 지속 저장하고 이름 등 Google 응답을 그대로 DB에 넣지 않는다.
- 상세 영업창은 regularOpeningHours의 주간 패턴을 요청 날짜/IANA 시간대에 투영한다.
  휴무는 빈 배열, 미상은 생략한다. 자정/주 경계, 24시간 영업과 DST를 처리한다.
  DST 모호/누락 시각을 임의로 보정하지 않고 제공자 오류로 반환한다. 임시/영구 폐업은 빈 창이다.
  공휴일 예외까지 보장하는 currentOpeningHours 결합은 후속 일정 생성에서 보완해야 한다.
- Google Maps 표시 문자열과 공급자 attribution을 응답에 전달한다. 실제 표시 UI는 T10/T13 책임이다.

## 이유

요구사항 §3은 구현 전에 최신 약관을 확인하도록 한다. 2026-11-18 확인한
[Google 서비스별 약관](https://cloud.google.com/maps-platform/terms/maps-service-terms)과
[Places 정책](https://developers.google.com/maps/documentation/places/web-service/policies)은
place ID 보관 예외와 좌표의 최대 30일 캐시를 명시한다. 전체 상세에도 같은 TTL을 적용할
근거는 확인하지 못했다. 따라서 보수적으로 좌표에만 캐시를 적용한다.

T8의 “같은 장소를 기한 내 다시 조회하면 외부 호출 0회”는 허용 필드인 좌표 조회에서
자동 테스트로 검증한다. **전체 상세 재조회까지 외부 호출 0회라는 해석은 충족하지 않는다.**
이 차이는 요구사항 변경으로 확정하지 않고 [질문 기록](../questions.md)에 사람 확인 사항으로 남긴다.

영구 저장소/청소 작업 없이 메모리와 실제 삭제 타이머를 사용하면 만료한 Google 상세가 DB나
백업에 남지 않는다. 프로세스 간 캐시 공유보다 저장 범위를 명확히 제한하는 것을 우선한다.
외부 SDK/HTTP 타입은 포트 밖으로 노출하지 않고 테스트는 합성 응답과 가짜 시계를 사용한다.

## 대안

- 전체 상세를 DB에 30일 저장: 좌표의 예외를 이름·영업시간에 확장할 근거가 없어 채택하지 않았다.
- 전체 상세의 짧은 메모리 캐시: 짧은 TTL도 명시적 예외가 아니므로 채택하지 않았다.
- 좌표 DB 캐시: 여러 인스턴스가 공유할 수 있으나, 실제 삭제 스케줄·백업 수명 관리가 필요하다.
  운영 환경이 확정되면 이 ADR과 저장소 계약을 갱신하면서 도입한다.
- 모든 필드 캐시 없이 호출: 약관 해석은 간단하지만 T9에서 좌표를 반복 조회하는 비용이 늘어난다.
