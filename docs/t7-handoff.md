# T7 수용량 검사 인계

`src/scheduler`의 `checkCapacity(input: ScheduleInput): CapacityResult`가 3단계 진입점이다.
T5의 날짜별 시간창과 T6의 대표 시각 이동 행렬을 그대로 받으며 DB나 외부 API를 호출하지 않는다.
기존 `scheduleVisits`의 인터페이스와 동작은 유지한다.

## 결과와 재검증

- `OK`: 요청한 필수 장소와 모든 고정 장소, 식사를 배치했다.
- `OVER_CAPACITY`: 전체 요청은 실패했지만 실제 배치에 성공한 부분 조합이 있다.
- `CONFLICT`: 모든 고정 항목과 식사·이동 제약을 유지하는 유효한 조합을 탐색에서 찾지 못했다.
  `recommendation`은 `null`이며 잘못된 N=0 추천을 만들지 않는다. 휴리스틱 실패로, 불가능성의 증명은 아니다.

`recommendation.requiredCount`가 추천 최대 필수 개수 N이고, `requiredVisitIds`가 해당 조합이다.
N은 최적값을 보장하지 않는다. 고정 필수 장소는 N에 포함하고 고정 희망 장소는 포함하지 않는다.
고정 희망 장소도 시간과 방문 순서를 소비하며 모든 고정 항목은 추천 탐색에서 유지한다.
일반 희망 장소는 자동으로 배치하지 않는다.

`recommendation.schedule`은 추천 조합을 원래 입력 순서로 다시 배치한 검증 결과다.
추천 ID에 없는 비고정 필수 장소를 `WISH`로 바꿔 `scheduleVisits`를 호출하면 같은 일정이 재현된다.
사용자가 다른 장소 조합을 선택한 경우에도 그 선택을 `REQUIRED`/`WISH`에 반영해 `checkCapacity`를 다시 호출한다.
같은 N개라는 이유만으로 통과시키면 안 된다. 고정 해제는 사용자의 별도 제약 변경으로 처리한다.
방문 ID는 고유해야 하며 중복이면 `RangeError`가 발생한다.

최상위 `unplaced`는 **원래 요청 전체**에서 실패한 장소 ID와 T6 사유(`TIME_WINDOW`, `UNREACHABLE`, `FIXED_ORDER`),
고정 여부를 담는다. `issues`에는 날짜별 식사 실패 또는 연결할 수 없었던 출발·도착 지점이 있다.
실패 사유는 해당 배치 시도의 진단이며 최소 충돌 집합이나 해당 장소 단독의 불가능성을 의미하지 않는다.
추천에서 제외된 장소 목록은 원래 필수 ID와 추천 ID의 차이로 구한다.

## 시간 비교와 탐색 방식

`time.availableMinutes`는 T5에서 항공·짐 처리 제약을 반영한 가용 시간창의 실제 경과 분 합계다.
`requiredMinutesLowerBound`는 요청 전체의 체류·식사 시간과 이동시간 하한의 합계다.
이동 하한은 각 방문으로 진입하는 최소 이동시간과 사용 가능한 각 날짜의 최소 복귀 이동시간을 더한다.
T6와 같은 택시 정책, 호출 버퍼, 짐 처리 플래그, 수동 이동수단을 적용한다.
필요한 진입·복귀 경로가 없으면 이동 및 전체 시간 하한은 `null`이며, 무한대나 NaN을 반환하지 않는다.
방문 순서, 장소 사이의 실제 연결, 영업시간, 고정 시각 대기를 완화한 하한이므로
가용 시간보다 작아도 실제 배치가 실패할 수 있다. 수용 여부와 N은 이 산술값으로 결정하지 않는다.

전체 배치 실패 후 미배치 비고정 장소를 제거해 재검증하고, 긴 체류부터 제외하는 대안으로 개수를 비교한다.
가장 좋은 유효 조합에 빠진 장소를 짧은 체류부터 다시 넣어 검증한다.
장소 삭제로 방향성 경로나 고정 순서가 깨질 수 있으므로 T6의 부분 일정을 그대로 추천하지 않는다.
검증된 일정만 보관하고, 입력 순서와 제약을 바꾸지 않는 결정적 탐색을 사용한다.

## 완료 기준 테스트와 후속 작업

`tests/scheduler-capacity.test.ts`에서 초과 상태, 배치 가능한 추천 N, 원인 장소 ID를 검증한다.
추천을 원래 입력에서 다시 실행하고 고정 위치·영업시간·겹침·식사·시간창을 확인한다.
다른 동일 개수 조합의 재검증, 닫힌 장소와 경로 누락, 고정 충돌, 빈 여행/N=0,
항공·식사 제약, 택시 정책과 수동 지정, DST, 3일·20개 장소의 1초 제한, 입력 불변성도 다룬다.

T7A는 이 인터페이스를 아키텍처 문서에 반영한다. T12는 실제 출발 시각 재조회 후 제약이 바뀌면 재검증하고,
T13은 원래 요청의 실패 진단과 검증된 추천을 구분해 보여준다. 실제 외부 연동은 이번 작업에 없다.
