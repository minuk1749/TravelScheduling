# T8: 장소 프록시와 캐시

## 변경 요약

- `src/places/`에 PlaceProvider, Google Places (New) 어댑터, 좌표 캐시, HTTP 처리기를 추가했다.
  서버 전용 `GOOGLE_PLACES_API_KEY`를 사용하며 빌드/import 시 API나 DB에 연결하지 않는다.
- 로그인 후 `GET /api/places?query=도쿄&regionCode=JP`로 한국어 검색한다. 지역은 선택 사항이고
  검색 결과는 첫 20개다. 상세는 `GET /api/places/{id}?timeZone=Asia/Tokyo&date=2026-11-23`,
  날짜는 반복 파라미터로 최대 31개 전달한다. 날짜를 생략하면 영업창 계산 대상은 없다.
- `GET /api/places/{id}?fields=location`은 장소 ID/좌표/만료 시각만 반환한다.
  기본 TTL 24시간, 1,000개 제한, 만료 타이머 삭제, 동시 조회 병합, 반환 객체 복사를 적용했다.
  상세 조회로 받은 좌표도 이 캐시에 반영한다.
- API는 인증 실패 401, 잘못된 입력 400, 장소 없음 404, 외부 장애/쿼터 503,
  잘못된 공급자 응답 502, 내부 오류 500을 구분하며 키/원문/SQL을 반환하지 않는다.
  HTTP와 Google fetch 모두 `no-store`다. 새 패키지나 DB 마이그레이션은 없다.

## 완료 기준 충족 근거

[places.test.ts](../tests/places.test.ts)는 실제 키 없이 합성 Google 응답과 가짜 시계로 검증한다.

| 기준/경계 | 자동 테스트 |
|---|---|
| 한국어 검색 | `T8 Korean search…`: 인증된 HTTP 처리 → 어댑터, 한국어 쿼리/언어/지역/필드 마스크와 한국어·현지어 결과 |
| 기한 내 같은 장소 재조회 시 외부 호출 0회 | `T8 same place location…`: 좌표 API를 반복 호출하고 fetch 호출 수가 1로 유지됨. 정확한 만료 경계와 다른 장소는 재조회 |
| 캐시 수명/격리 | 동시 요청 병합, 반환 객체 변경 격리, 용량 퇴출, 조회 없는 만료 삭제, 상세 응답에서 좌표만 추출 |
| 영업시간/오류 | 주말 자정 통과, 24시간/DST, 휴무/미상, 인증/입력, 404/쿼터/네트워크/잘못된 JSON과 오류 비공개 |

**전체 상세 재조회 시 외부 호출 0회는 충족하지 않는다.** 캐시 허용 필드만 대상으로 한
위 검증을 전체 상세 캐시로 해석하면 안 된다. 테스트는 이름/영업시간/검색 결과를 캐시하지
않는 것도 명시적으로 검증한다. 근거는 [ADR 0003](decisions/0003-places-cache-policy.md)이다.

2026-11-18 최종 검증(Node 24.22.3):

- `npm run lint`: 통과.
- `npm run typecheck`: 통과.
- `npm run build`: 통과. 두 장소 API와 PWA 산출물 확인.
- `npm test`: 총 54개 중 50개 통과, 4개 실패, skip 0개. 신규 T8 9개는 모두 통과.
  기존 DB 테스트(auth 1개, db 1개, travel-model 2개)는 `DATABASE_URL` 미설정으로 실패했다.
  DB 테스트를 변경하거나 건너뛰지 않았다. PostgreSQL 16이 있는 CI에서 재검증해야 한다.
- 기본 셸은 Node 26이어서 임시 npm 캐시의 Node 24를 통해 위 명령을 실행했다.
  저장소 의존성/package-lock은 변경하지 않았다.

## 남은 이슈 / 가정

- [질문 기록](questions.md)의 완료 기준 해석 차이는 사람 확인 전이다. 요구사항 파일은 바꾸지 않았다.
- 캐시는 프로세스별 메모리다. 재시작·여러 인스턴스·용량 퇴출은 캐시 미스로 이어진다.
- 영업창은 regularOpeningHours 기준이다. 공휴일/특별 영업시간은 아직 결합하지 않는다.
- 기존 places의 이름/좌표/JSON 열에 원본 Google 응답을 저장하지 않는다. 장소 ID의 영구 저장과
  여행 연결은 T10 입력 저장소에서 담당한다.

## 사람 확인 필요

- 좌표 재조회에 한정한 캐시 완료 기준 해석. 전체 상세 캐시가 필요하다면 별도 허용 근거 또는
  제공자 선택을 먼저 결정해야 한다.
- 실제 서버 키로 Places API (New) 활성화/키 제한/한국어 검색·상세/쿼터 설정을 확인한다.
- T10/T13에서 Google Maps 표시와 응답의 공급자 attribution을 실제 화면에 표시하고,
  서비스 이용약관/개인정보 안내를 준비한다. 실제 키를 사용한 확인은 수행하지 않았다.

  공휴일/특별 영업시간을 고려한 재검증을 추가해야 한다.
