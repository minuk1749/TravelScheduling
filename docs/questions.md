# 에이전트 질문과 가정

요구사항이 모호할 때 에이전트가 질문과 채택한 가정을 기록한다. 사람이 답하면 `docs/requirements.md`에 반영하고 여기서는 "답변 완료"로 표시한다.

| 2026-11-18 | T9 | 같은 이동시간 요청의 반복 호출 0회를 Google 응답에도 적용할 수 있는가? | 일반 제공자용 유한 TTL 메모리 캐시와 호출 0회 테스트를 구현한다. 최신 Google Routes 약관에서 시간·거리·요금 보관 허용을 확인하지 못했으므로 Google 기본 팩터리는 완료 응답을 저장하지 않고 진행 중 동일 요청만 합친다. ## T19 가정과 병행 작업 인계

- 기준 develop `0b1aab5`, 작업 브랜치 `t19-local`. 실행 지시가 보호 파일 수정을 금지하므로 tasks의 기존 진행중/gpt 상태를 유지하고 브랜치 열은 수정하지 않는다. 커밋·푸시·PR 생성은 러너가 담당한다.
- T18이 진행 중이므로 인증 구현을 중복 작성하거나 해당 파일을 수정하지 않는다. 새 `route-shapes/http.ts`는 `userId(request)`를 받는다. 현재 조립은 쿠키 인증이며 Authorization이 있으면 401로 닫는다. T18 통합 시 `route-shapes/server.ts`에 공통 RequestAuthenticator 연결과 Bearer 소유권 회귀 검사가 필요하다.
- 삭제된 장소로 `PlaceProvider.location`이 null이면 해당 구간도 명시적 `NONE`으로 반환한다. 제공자 장애는 null로 처리하지 않는다. 결과 미저장은 RESULT_UNAVAILABLE, 저장 결과는 있으나 현재 입력이 불완전하거나 해시가 다르면 STALE_INPUT이다.
- 모양 표시만을 위한 Google 재조회이므로 저장 당시와 제공자 경로가 달라질 수 있다. 현재 선택 수단·출발 시각을 유지하며 동선·요금·시간을 재계산하지 않는다. 상세: [T19 결정](decisions/T19-route-shapes.md).

## T21 모바일 입력 가정

| 질문 | 채택한 가정 |
|---|---|
| 여행 기본 입력에서 장소 추가로 이동할 때 언제 저장하는가? | 기존 여행 생성 API는 방문 장소가 필요하다. 두 화면은 메모리 초안으로 유지하고 ‘동선 만들기’에서 방문·생활·고정 조건을 함께 저장한 뒤 계산한다. 다시 열 때는 소유 여행 목록에서 저장값을 읽고 하루 생활을 기존 설정 API로 수정한다. |
| 장소를 지도나 직접 입력한 주소로 고를 때 어떤 값을 저장하는가? | 지도에서는 Google POI를 눌러 선택하고, 주소는 한국어 장소 검색에서 주소를 조회해 결과를 선택한다. 지도에 표시된 장소를 고르거나 주소 검색 결과에서 선택하고, 저장에는 Google 장소 ID를 사용한다. |
| 도시 비교에 필요한 시간·요금이 도시 프로필에 없으면 어떻게 하는가? | 대중교통 운행 시간과 택시 호출 대기·추정 요금표, 도보 무료와 API의 추천 정책을 표시한다. 출발지·도착지별 시간이나 요금은 ‘—’로 표시한다. 구간 값은 T22 결과 화면에서 제공한다. |
| 초기에 희망 장소에 고정 조건을 지정할 수 있는가? | 장소 추가 시 희망으로 바꾸면 고정 조건을 제거한다. 경로에 희망을 수동 추가하는 작업은 결과 화면에서 수행한다. |
| 계산 뒤에는 어떤 화면을 제공하는가? | T21 생성 화면이 기존 API의 성공·초과·충돌·실패 상태를 표시한다. 상세 결과·지도 및 필수 장소 재선택은 각각 T22·T23 범위다. |

## T22 결과 화면 가정

| 질문 | 채택한 가정 |
|---|---|
| T23 `동선 보기`의 읽기 전용 일정은? | T22 결과 화면으로 바꿨다. 검증된 응답과 저장 입력을 메모리로 넘기므로 다시 계산하지 않는다. 임시 화면(`verified-schedule.tsx`)은 지웠다. |
| 3-5 "생성 중"은 어디서 보이는가? | 최초 계산에서는 지도와 결과 패널 요약 줄에 진행 표시를 띄운다. 응답을 받기 전에는 카드와 구간을 비운다. 재계산에서는 이전 카드를 50%로 표시하고 바뀌는 구간을 숨긴다. |
| API가 한 번에 결과를 돌려주는데 "계산이 끝난 구간만" 그리는 기준은? | 수단 변경 시 해당 구간을, 장소 수정 시 그 장소의 도착·출발 구간을 숨긴다. 희망 장소를 추가하거나 방문 날짜를 옮기면 삽입 순서가 정해질 때까지 목적 날짜의 일반 이동 구간도 숨긴다. 공항 이동과 관련 없는 날짜의 구간은 유지한다. 실패 뒤 저장부터 재시도하면 원래 편집 기준을 쓰고, 계산만 재시도하면 응답이 올 때까지 모든 구간을 숨긴다. |
| 선택하지 않은 일정 마커의 테두리는 §6 "도착 구간 순서 색"인가, §7 "`#2A64A8`"인가? | R2 결과 화면의 기준인 §7을 따라 블루 테두리와 `#1D4F8A` 번호를 쓴다. 구간 순서 색은 경로 선, 전체 일정의 번호 타일·이동 아이콘에 쓴다. |
| 지도 경로 표현을 네이티브 지도에서 그대로 그릴 수 있는가? (요구사항 §5 주의) | 어댑터 안에서 가까운 표현으로 대신한다. 도로 색 바꾸기는 흰 테두리 선 위에 순서 색 선을 그린다. 떠 있는 곡선은 2차 곡선 점선과 땅 위 직선 그림자(12% 회색)로 그린다. 차선처럼 나눠 그리기는 하지 않는다: 같은 도로를 지나는 두 구간은 겹치며, 진한 구간을 위에 그린다. 마커 강조는 1.3배·바깥 링으로 정적으로 그린다. 카드 넘김 곡선과 같은 애니메이션은 적용하지 않았다. 모두 기기에서 사람이 확인한다. |
| 여행 전체 효율 요약은 R2 화면 어디에 두는가? | 7절에 자리가 없어 "전체 일정" 시트 아래에 둔다. 표시 항목은 대중교통·도보만, 선택한 이동, 단축 시간이다. |
| 아이콘은? | 벡터 아이콘 패키지를 추가하지 않고 글자 기호를 쓴다(🚇 🚕 🚶 ⌂ ✈ ★ ⚙ ☰ ◎ ⇄). 이모지인 수단 아이콘은 색(`#2A64A8`)을 입힐 수 없고, 옆 글자가 의미를 전달한다. 아이콘 세트 도입은 사람 결정 사항이다. |
| 도심 범위는 어떻게 정하는가? | 도시별 중심 좌표와 반지름 원으로 정한다(`CITY_CENTRES`). 예: 도쿄 5km(야마노테선 근사), 오사카 3.2km(순환선 근사). 프로필이 없는 도시는 직선거리 4km 규칙만 쓴다. 값은 조정할 수 있다. |
| 충돌(3-8) 결과에는 일정이 없는데 카드는 무엇을 보여 주는가? | 같은 화면의 마지막 OK 결과 카드를 보여 주고 원인 장소에 경고와 사유를 붙인다. 일정에 없는 원인 장소는 고정 날짜(없으면 첫날)에 위치 없는 카드로 추가해 먼저 선택한다. 날짜 단위 원인(이동 불가 구간·공항·항공)은 사유 줄로 보이고, 이동 불가 구간은 레드 곡선으로 그린다. 충돌 중에는 넘김 줄 대신 `○○ 고정 수정`·`변경 취소`를 둔다. 원인 장소가 없으면 `여행 조건 수정`을 둔다. |
| 결과 화면을 다시 열 때 저장된 일정을 읽는가? | T16 가정대로 소유자용 GET을 추가하지 않았다. 생성 화면이 POST로 계산하고 결과 화면은 그 응답을 쓴다. 계산 비용이 문제가 되면 공유 결과 읽기와 같은 방식의 GET을 별도 작업으로 추가한다. |
| 빈 날짜의 "여유 시간"은? | 생성 응답의 `availableByDate`에서 공항 이동과 항공 일정을 반영한 날짜별 가용 구간을 여행 시간대로 표시한다. 닫힌 날은 “여유 시간 없음”, 이전 응답에 필드가 없으면 “여유 시간 정보 없음”으로 표시한다. |
| 현재 위치 버튼은? | `react-native-maps`의 사용자 위치 표시를 켜고 위치로 카메라를 옮긴다. Android는 실행 중 권한을 요청하고, iOS는 위치 사용 설명을 앱 설정에 넣었다. 위치는 저장하거나 서버로 보내지 않는다. |
| 이동수단 바꾸기 외에도 토스트를 띄우는가? | 모든 수정 재계산 뒤에 띄운다. 제목은 변경 종류별로 다르고, 바뀐 장소의 분 변화와 고정 예약 유지 여부를 붙인다. `되돌리기`가 있고 6초 뒤 닫힌다. |
