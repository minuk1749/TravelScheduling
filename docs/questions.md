# 에이전트 질문과 가정

요구사항이 모호할 때 에이전트가 질문과 채택한 가정을 기록한다. 사람이 답하면 `docs/requirements.md`에 반영하고 여기서는 "답변 완료"로 표시한다.

| 날짜 | 작업 | 질문 | 채택한 가정 | 상태 |
|---|---|---|---|---|
| 2026-11-18 | T1 | PWA의 오프라인 범위와 DB 도구는? | 오프라인은 요구사항에서 제외되어 서비스워커는 네트워크만 사용한다. DB는 pg 연결 풀만 추가하고 스키마/마이그레이션은 T3에서 정한다. 기존 CI의 PostgreSQL 16과 테스트 스크립트를 사용하며 보호 파일은 수정하지 않는다. | 채택 |
| 2026-11-18 | T2 | T3 이전에 여행 소유권과 탈퇴 삭제를 어떻게 검증할까? | T2에 사용자와 소유자만 있는 최소 trips 테이블을 도입한다. T3의 여행 데이터는 trips에 삭제 연쇄 외래 키를 연결한다. 탈퇴 후 기존 세션도 사용자 존재 여부를 확인해 무효화한다. | 채택 |
| 2026-11-18 | T3 | 기존 T2 여행과 세부 구조가 아직 정해지지 않은 식사·경로 비교 데이터를 어떻게 보존할까? | 기존 소유자 전용 여행 행은 유지하고 새 여행 필드는 기존 행에 한해 비어 있을 수 있도록 한다. 식사 슬롯·시간대와 경로 대안 등 향후 작업에서 구체화할 구조는 JSONB로 저장하고, 현지 항공 일시는 여행의 IANA 시간대와 함께 해석한다. 장소 캐시는 사용자 소유 여행과 분리한다. | 채택 |
| 2026-11-18 | T4 | 심야 할증률과 적용 시각 및 경계 구간은 어떻게 해석할까? | 도시별 할증률은 기본·거리·시간 요금 합계에 적용하는 비율(0.2 = 20%)이며, 출발 시각을 여행의 IANA 시간대로 변환해 시작 포함·종료 제외 구간에 적용한다. 자정 통과 구간을 지원하고 시각과 요율은 함께 지정한다. 호출 대기는 요금 계산에 포함하지 않는다. 실제 요금표와 반올림 규칙은 T4D에서 확인한다. | 채택 |
| 2026-11-18 | T5 | 공항 경유 시간과 식사 슬롯의 정확한 배치 시간은 어떻게 정할까? | 호출자가 공항과 일정 시작·종료 지점 사이의 전체 이동시간(숙소 경유 및 짐 처리 시간 포함)을 제공하고 경유 여부를 명시한다. 입국 90분·출국 150분을 기본 버퍼로 적용한다. 식사 소요시간과 이동시간을 모르는 1–2단계에서는 각 식사의 가용 시간창을 활동 시간과 교차해 반환하며 교차가 없으면 null로 알린다. 시간창은 같은 현지 날짜의 시작 포함·끝 제외이며 DST의 모호하거나 존재하지 않는 현지 시각은 거부한다. | 채택 |
| 2026-11-18 | T6 | 고정 순서, 식사 위치와 시간, 행렬 요금·짐 처리 정보는 어떻게 전달할까? | 고정 순서는 식사를 제외한 날짜별 방문의 0부터 시작하는 위치이며, 고정 시각과 영업시간은 오프셋이 있는 시각으로 받는다. 알 수 없는 영업시간은 생략하고 빈 배열은 방문 불가로 처리한다. 식사는 호출자가 제공한 소요시간 동안 직전 지점에서 확보하고, 장소가 지정된 식당 방문은 별도 방문으로 취급한다. 날짜별 방향성 행렬의 택시 시간은 호출 대기를 제외하고, 비교 요금은 같은 현지 통화로 받는다. 짐 구간과 수동 이동수단은 호출자가 날짜별 출발·도착 지점 쌍으로 지정한다. 첫날·마지막 날의 공항 이동시간은 T5에서 이미 반영한다. 필요할 때만 정책의 예외가 적용되지 않으면 15분 이하 도보를 우선하며, 대중교통이 없으면 택시가 가능한 경우 택시를 쓴다. 요금 정보가 없으면 비용 효율 조건은 충족하지 않은 것으로 본다. | 채택 |
| 2026-11-18 | T7 | 추천 개수, 고정 항목 충돌과 필요 시간을 어떻게 표현할까? | N은 실제 재배치에 성공한 필수 장소 개수(고정 필수 포함)이며 최적값은 아니다. 고정 희망 장소는 시간을 소비하지만 N에 포함하지 않고 모든 고정 항목은 추천 탐색에서도 유지한다. 전체가 실패하고 검증된 부분 조합이 있으면 OVER_CAPACITY, 식사·고정 항목 등을 유지하는 유효한 조합을 휴리스틱으로 찾지 못하면 CONFLICT와 null 추천을 반환한다(불가능성의 수학적 증명은 아님). 필요한 시간은 체류·식사와 정책/수동 지정에 따른 최소 진입·복귀 이동시간의 하한으로 표시하며 대기·순서·영업시간은 실제 배치로 검증한다. 필수 이동 경로가 없으면 시간 하한은 null이다. 사용자가 다른 조합을 선택하면 비고정 장소의 REQUIRED/WISH를 변경해 같은 검사 함수를 다시 호출한다. | 채택 |
