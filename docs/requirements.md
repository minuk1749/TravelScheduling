## 1. 서비스 개요

해외 자유여행자를 위한 동선 추천 PWA. 사용자가 항공 일정, 숙소, 가고 싶은 장소(식당·명소)를 입력하면
대중교통·도보·택시 기준 이동시간과 식사시간을 고려해 날짜별 일정을 자동 생성한다.
도시별로 택시와 대중교통의 시간·요금 효율을 비교해 보여주고, 그 결과로 택시 사용 정책을 고르게 한다.

- **사용자:** 해외 도시를 여행하는 한국어 사용자(Google 로그인)
- **이번 버전 제외:** 항공·숙소 예약, AI 장소 추천, 실시간 교통, 정확한 요금 결제·견적(요금은 추정치만), 오프라인 모드, 공동 편집, 다국어

### 핵심 사용자 흐름
1. Google 로그인
2. 여행 생성(도시, 기간) → 그 도시의 **이동 프로필**(택시 vs 대중교통 비교)과 추천 택시 정책 표시
3. 항공편 수동 입력(도착 공항·현지 도착 시각, 출발 공항·현지 출발 시각)
4. 숙소 입력(숙박 기간별 복수 가능)
5. 장소 추가(식당/명소, 체류시간)
6. 생활 설정: 날짜별로 숙소에서 나가는·들어오는 시각, 끼니 수, 식사 시간대, 택시 정책(사용 안 함 / 필요할 때만 / 선호)
7. 동선 생성
   - 수용량 초과 → 초과 사실과 추천 최대 필수 개수 N 안내 → 필수 장소 선택 → 재검증
8. 결과 확인: 날짜별 타임라인과 지도
   - 지도: 배치된 장소와 **희망 장소(미배치)**를 다른 마커로 구분
   - 구간별 대중교통 vs 택시 비교(시간, 추정 요금), 여행 전체 효율 요약
9. 수정·고정: 희망 장소를 지도에서 날짜에 추가, 순서·이동수단 변경 → 재계산
10. 읽기 전용 링크 공유

## 3. 기술 제약 및 주의사항

1. **최대 필수 개수는 추정값이다.** 시간 제약 안에서 방문 수를 최대화하는 문제(Orienteering Problem)는 최적해를 빠르게 구할 수 없다.
   휴리스틱으로 배치에 성공한 조합의 개수 N을 안내한다. 추천 조합은 배치가 보장되고, 사용자가 다른 조합을 고르면 다시 검증한다.
2. **대중교통 소요시간은 출발 시각에 따라 달라진다.** 순서는 날짜별 대표 시각 기준 행렬로 정하고, 확정된 구간은 실제 출발 시각으로 다시 조회한다.
3. **Google 약관상 캐시에 제한이 있다.** place_id는 영구 저장할 수 있고, 좌표 등 상세 정보는 캐시 기간이 제한된다(구현 전에 최신 약관 확인).
4. **요금 데이터:**
   - Google Routes는 **택시 요금을 제공하지 않는다.** 그래서 도시별 택시 요금표(기본요금, km당, 분당, 할증)를 직접 관리하고, 추정 요금 = 기본요금 + 거리 × km당 요금 + 시간 × 분당 요금으로 계산한다.
   - 요금표에는 출처와 갱신일을 함께 저장하고, 화면에는 "추정"이라고 표시한다.
   - 대중교통 요금은 Routes API가 **일부 지역에서만** 제공한다. 제공하지 않는 구간은 "요금 정보 없음"으로 표시한다.
   - 택시 소요시간 = DRIVE 소요시간 + 호출·대기 버퍼(도시별, 기본 10분).
5. **개인정보:** 로그인 도입으로 개인정보 보호법이 적용된다. 처리방침 고지, 최소 수집(Google ID·이메일), 회원 탈퇴 시 데이터 삭제가 필요하다.
6. 추후 iOS 네이티브 앱으로 전환하면서 Google 로그인을 쓰면 Apple 로그인을 함께 제공해야 할 수 있다(App Store 심사 지침).

## 4. 구조

```
[PWA] 입력 · 이동 프로필 · 생활 설정 · 필수 장소 선택 · 타임라인/지도
   │ 세션(Auth.js, Google)
[API 서버]
  ├─ Auth ───────────────────────────── users
  ├─ Trip CRUD (소유자 검증, 공유 토큰) ─ PostgreSQL
  ├─ Place 프록시 ── Google Places
  ├─ TravelTime ──── Google Routes (TRANSIT/WALK/DRIVE)
  ├─ Fare ────────── 도시 이동 프로필·택시 요금표(DB, 시드 데이터) + 환율
  └─ Scheduler (순수 함수, 외부 의존 없음)
```

### 데이터 모델
| 엔티티 | 주요 필드 |
|---|---|
| `User` | id, googleId, email, createdAt |
| `CityProfile` | 도시 코드, 국가, 통화, 대중교통 평가(커버리지·운행 시간), 택시 요금표(기본요금/km당/분당/심야 할증), 호출 버퍼, 효율 기준값, 차량 호출 앱 정보, 출처, 갱신일 |

### 스케줄러 처리 단계
1. 날짜별 가용 시간창 계산: 활동 시간(날짜별) ∩ 항공·짐 처리 제약
2. 식사 슬롯 확보(날짜별 끼니 설정)
3. 수용량 검사 → 초과면 `OVER_CAPACITY`, 추천 최대 개수 N, 추천 조합, 필요 시간 vs 가용 시간을 반환하고 종료
4. 고정 항목 배치(사용자가 지도에서 날짜에 추가한 희망 장소 포함)
5. 필수 장소를 지리적 군집에 따라 날짜에 배분
6. 날짜 내 순서 결정(시간창 제약 + 탐욕적 삽입 + 2-opt). 구간별 이동수단 선택 포함
7. 실제 출발 시각으로 구간 재조회 → 영업시간 재검사 → 위반이 있으면 6단계부터 다시 수행
8. 구간별 대안 비교와 여행 전체 효율 요약 계산

희망 장소는 스케줄러가 자동으로 넣지 않는다.

### 이동수단 선택 규칙 (사용자가 구간별로 지정한 이동수단이 항상 우선)
| 정책 | 규칙 |
|---|---|
| 사용 안 함 | 대중교통 또는 도보만 사용. 둘 다 불가능하면 "이동 불가" 경고 |
| 필요할 때만 | 기본은 대중교통 또는 도보(도보 15분 이하 구간은 도보). 다음 중 하나면 택시: (a) 대중교통 경로 없음 (b) 아낀 시간 ≥ 20분이고, 아낀 1분당 추가 비용 ≤ 도시 기준값 (c) 첫날·마지막 날 짐을 들고 이동하는 구간 |
| 선호 | 도보 15분을 넘는 구간은 택시. 단 대중교통이 택시보다 빠르면 대중교통 |
